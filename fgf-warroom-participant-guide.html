Setup

Do this once per team before Challenge 1. These steps spell out every click — if you've never used Databricks, just follow them in order. Pick one teammate as the driver to run the terminal commands (steps marked Driver); everyone else follows along in the UI.

Before you start: in the commands below, replace <your-team> with your team name (e.g. team1), <your-email> with your Databricks login email, and <your-warehouse-id> with the ID you copy in Step 2. Wherever you see teamN, it means your team (e.g. team1). Type terminal commands one line at a time.
  1. Open the project as a Git folder.
    • In the left sidebar, click Workspace.
    • Click the blue Create button (top-right) → Git folder.
    • In Git repository URL, paste https://github.com/subhannita1994/fgf-agent-ops-war-room — the folder name fills in automatically — then click Create Git folder.
    • Open the new fgf-agent-ops-war-room folder. At the top, next to the folder name, is a branch button that reads main. Click it and switch to your team's branch (e.g. team1).
  2. Copy your SQL Warehouse ID.
    • In the left sidebar, click SQL Warehouses.
    • Find your team's warehouse named teamN-starter and click it.
    • On the Overview tab, copy the Warehouse ID (a long string of letters and numbers). You'll paste it into the commands below.
  3. Driver Open the web terminal and deploy the stack.
    • In your Git folder, open any notebook, and in the compute dropdown (top-right) attach it to Serverless.
    • At the bottom-right of the screen, click the web terminal icon to open a terminal.
    • Run these two commands, one line at a time:
    cd /Workspace/Users/<your-email>/fgf-agent-ops-war-room
databricks bundle deploy --var team=<your-team> --var warehouse_id=<your-warehouse-id>
    • Wait until it finishes with no errors.
  4. Confirm the deploy created three things.
    • Left sidebar → Jobs & Pipelines: you should see a job teamN-nightly-refresh and a pipeline teamN-sales-orders.
    • Top-right 9-dots menu (beside your initials) → Databricks Apps: you should see teamN-sales-agent. It will say Stopped for now — that's expected.
  5. Load the demo data. In the Git folder, open data/00_seed_sales_orders and click Run all at the top. When it finishes (a few minutes), open Catalog in the left sidebar → your catalog → schema teamN: you should see 16 tables and 1 volume named landing.
  6. Create the agent's tools. Open tools/01_create_uc_functions and click Run all. Back in Catalog → teamN → Functions, you should see 9 functions.
  7. Give the app permission to your data. Open setup/01_grant_app and click Run all. This grants the app's service principal access to your schema.
  8. Driver Start the app. Back in the web terminal, run: 
    databricks bundle run sales_agent --var team=<your-team> --var warehouse_id=<your-warehouse-id>
  9. Open the app and test it. Top-right 9-dots → Databricks Apps → teamN-sales-agent. Wait until the status shows Running, then click the app URL to open it. Click any question in the left sidebar — you should get an answer with a footer line. You're ready for Challenge 1.
Tip: the app's sidebar has the full question bank as buttons, an “Alert me if it gets worse” button, and a Run health check button. These are your instruments all afternoon.

Challenge 1: Genie ZeroOps

Something upstream broke, and nobody was paged Genie ZeroOps

Goal: Find out which part of the data pipeline broke and why. Rather than digging through logs and run histories yourself, you'll use Genie ZeroOps.

Reproduce it

Run the teamN-nightly-refresh job and watch it fail. Because the job failed, no fresh data reaches the agent, so its answers are stuck on old data.

Investigate

Before changing any code, let Genie ZeroOps do the detective work — point it at the failed teamN-nightly-refresh job and have it find the root cause. Then apply the fix and push it to your team branch.

Checkpoint questions

Answer these before you pass. Stuck? Reveal a hint — hint usage is recorded.

Hint Reveal
You can look into the failing SDP's error message.
Hint Reveal
After the code fix, use Genie ZeroOps to update the bad landing file in sales_order_header/daily_drop_*.json.
🏁 Pass this round when the nightly-refresh pipeline runs successfully end to end.

Challenge 4: Unity Gateway

Ungoverned model calls, runaway cost, leaked PII Unity Gateway

Goal: Put every model call behind a governed path.

Reproduce it

Ask Q11. Oh no — you get a buyer's raw personal contact details (PII alert!).

Investigate

Aim for two outcomes: the buyer's phone number comes back masked (no raw PII leaks), and model usage is held in check by rate limits so token cost stays under control. How you get there is up to you.

Checkpoint questions

Hint Reveal

Challenge 5: Databricks Apps Bonus / Take-home

“Alert me” dies when the tab closes Databricks Apps

Goal: Durable alerting that keeps watching with no one looking and reaches the whole team.

Reproduce it

Ask Q13 or click “Alert me”. It works while you watch — but close or refresh the tab and it stops, and only you ever saw it.

Investigate

Aim for an alert that keeps running after the browser tab closes and reaches the whole team — not just the person who clicked — with no one watching. The in-session loop can't do that; it's up to you to find a durable, scheduled way to get there.

🏁 Pass this round when a scheduled, outside-the-session mechanism replaces the in-browser loop and keeps alerting with the tab closed.
